# CLAUDE.md — invariants for Velocia

These rules hold in every task. If a task seems to require breaking one, stop and ask.

## Measurement integrity
- Every speedup is reported as a ratio of medians with a 95% confidence interval. Never a bare "3.2x".
- A result without a passing correctness checksum against the reference engine is a failed run, shown as failed.
- Every run writes a manifest (image digests, versions, config hash, hardware, dataset). No manifest, no result.
- Results are compared only within one hardware manifest unless the user overrides explicitly.
- Never claim results are official TPC results. Label them "derived from TPC-H / TPC-DS".

## Independence
- Velocia has no runtime dependency on any other analysis tool or service. Integration happens only through the benchmark bundle export.
- Velocia starts no services of its own except the optional localhost viewer. Ephemeral Spark containers or pods created for one run and always removed afterwards are not services.

## Privacy and security
- Secrets in Spark configs and environment are redacted before anything is written to the results directory, a report or a bundle.
- No telemetry, no phone-home, ever.
- Never commit event logs or data from any employer or customer. Test data is generated by this repo.

## Engineering
- The event-log reader streams line by line and never loads a whole log into memory.
- Public interfaces (CLI flags, config and experiment schemas, results and bundle formats) change only with a spec update and a changelog entry.
- Product name: "Velocia for Apache Spark". Never "Spark X". Write "Apache Spark" in first and prominent mentions.
